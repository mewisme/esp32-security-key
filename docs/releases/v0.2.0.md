# MultiKeys v0.2.0

First release with **prebuilt firmware** next to the host tools. One release, one version number for both.

> **Experimental development firmware — not suitable for protecting important accounts.** It uses a development USB
> VID:PID (`303A:4002`, a placeholder) and a development AAGUID, has no Secure Boot and no flash encryption, is not FIDO
> certified and has been tested on one board type only.

## Assets

| File | What |
|---|---|
| `multikey-firmware-v0.2.0-esp32s3-n16r8-fido-dev.zip` | FIDO2 development firmware for an ESP32-S3 N16R8 board, BOOT button (GPIO0) as the touch button, no LED: `bootloader.bin`, `partition-table.bin`, `multikey-fido.bin`, `firmware.json`, `SHA256SUMS`, `LICENSE`, `NOTICE.txt`, `README.txt` |
| `firmware-manifest.json` | machine-readable description of the firmware (offsets, sizes, SHA-256, partition layout); read by the web installer |
| `multikey-v0.2.0-windows-x86_64.zip` | `multikey.exe` for Windows 10/11 x86_64 |
| `multikey-v0.2.0-linux-x86_64.tar.gz` | `multikey` for Linux x86_64 |
| `multikey-pam-v0.2.0-linux-x86_64.tar.gz` | `pam_multikey.so`, the PAM module for MKAUTH login keys |
| `SHA256SUMS` | checksums of the five files above |

The OpenPGP image is not published; build it from source (`docs/FLASHING_ADVANCED.md`).

## Install the firmware

- **Web installer:** https://multikeys.mewis.me (desktop Chrome or Edge). Status at the time of this release: see the
  README "Install MultiKeys" section; the web installer is only called hardware-verified there once it has been tested on a
  real board.
- **Manual:** unzip the firmware archive and follow its `README.txt` (one `esptool write_flash` command with the three
  offsets). It never erases the whole chip; the credential area (`part0`) is not written.
- **From source:** `tools/flash-dev.ps1` as before.

Updating a key that runs firmware from before v0.2.0: the partition layout is unchanged, so stored credentials are not
written, but older firmware does not declare a data format version; the web installer asks you to acknowledge this.

## Firmware changes

- The firmware version (`esp_app_desc_t`) now follows the release version (`0.2.0`); local builds report `0.2.0-dev`.
- The WebUSB landing page is now `https://multikeys.mewis.me` (keys flashed earlier keep the old GitHub URL until reflashed).

## Host-tool changes since v0.1.0

- Windows trust store moved to `%ProgramData%\MultiKeys\trusted.toml`; an existing `%ProgramData%\MultiKey\trusted.toml`
  is still used when it is the only one.
- The product is consistently named "MultiKeys" in help text and documentation (binary and crate names are unchanged).

## Verify

`sha256sum -c SHA256SUMS --ignore-missing` (Linux) or `Get-FileHash -Algorithm SHA256 <file>` (Windows), compared with
`SHA256SUMS`. Inside the firmware zip: `sha256sum -c SHA256SUMS`. Checksums protect against corrupted downloads, not against a
compromised repository or release; nothing is signed.
