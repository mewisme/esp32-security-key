# MultiKeys v0.3.5

This release carries the fixes from a full security audit of the firmware, the MKAUTH applet, the host tools and the web
installer. Supported boards are unchanged (4, 8 and 16 MB ESP32-S3). It is the first release whose manifest is signed
(`firmware-manifest.json.sig`, key id `release-2026-a`, `docs/RELEASE_SIGNING.md`).

> **Experimental development firmware — not suitable for protecting important accounts.** It uses a development USB
> VID:PID (`303A:4002`, a placeholder) and a development AAGUID, has no Secure Boot and no flash encryption and is not FIDO
> certified. The OpenPGP image has additionally **never been run on a board**.

## What changed in the firmware

- **Memory safety.** `getPinToken` checks the length of `pinHashEnc` before a PIN retry is spent and `decrypt()` rejects lengths that
  are not whole AES blocks (a stack overflow); `ecdh()` checks the peer point and its result; `credential_verify` no longer
  underflows on credential IDs of 32-47 bytes; U2F key-handle lengths are checked; duplicate CBOR keys are rejected. Chained APDUs
  can no longer overflow the CCID buffer (ported from upstream pico-keys-sdk 325c0a9). Flash erase/program errors are no longer
  ignored.
- **Attack surface.** The vendor commands BACKUP, MSE, UNLOCK and EA (reachable with only a button press) and the management
  applet's write-config and reset commands are removed. U2F register honours `alwaysUv`. The CTAP reset window after power-up is
  enabled (`authenticatorReset` works only within 10 s of plugging in and needs the BOOT button).
- **USB/HID.** While a command runs, other channels get `CHANNEL_BUSY` and cannot touch the shared buffers; `WINK` no longer blocks;
  channel IDs are random. A broadcast `CTAPHID_INIT` during a running command now answers `CHANNEL_BUSY` instead of aborting it.
- **MKAUTH.** The button is required before a PIN is checked (a timeout spends no retry); the retry counter lives in its own file
  (`0xBC02`); the PIN verifier uses PBKDF2 (record version 2, version 1 records are upgraded on the first correct PIN); a corrupt
  record answers `6F00` instead of looking unenrolled. OpenPGP TERMINATE and PIV reset no longer erase MKAUTH data.
- **OpenPGP/PIV (experimental, not run on a board).** Length checks, session clean-up, user-interaction defaults on for new storage.
- **Build.** Release builds get a hardening layer (silent panic, no console, stack protector, heap poisoning). `--harden` requires
  `--release` and a board; the eFuse-writing code path of the upstream SDK was removed.

## What changed in the web installer and host tools

Deployed separately from this release. The installer verifies the packaged partition table and the image headers, checks the
manifest's USB VID:PID, caps zip members at 4 MiB, requires an extra acknowledgement for an unsigned release, and the Worker
caps proxied assets while streaming. The host library rejects device names with control characters and a policy without user
presence.

## Status

- **Not hardware verified.** The firmware is build verified (4, 8 and 16 MB) and tested with the native emulation (66 tests) only.
  The 16 MB FIDO2 image was flashed to the N16R8 board before release, but no functional test was run on it.
- **Signed with a new key.** The signature is only checked by site versions that list `release-2026-a`.
- Known and not fixed: MKAUTH transcripts are not bound to the context (needs protocol v2, `docs/PROTOCOLS.md`); the silent
  credential tag is not derived from the device key; the `crypto-bigint` timing advisory (RUSTSEC-2026-0387) is accepted
  (`docs/DEPENDENCIES.md`).
- Stored data format is unchanged (`data_preserving_from` stays `0.2.0`) except the MKAUTH record version, by code inspection only.
