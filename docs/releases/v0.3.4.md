# MultiKeys v0.3.4

This release carries the firmware fixes and safety checks from a security hardening pass. The host tools are unchanged apart from the
version number. The supported boards are the same (4, 8 and 16 MB ESP32-S3).

> **Experimental development firmware — not suitable for protecting important accounts.** It uses a development USB
> VID:PID (`303A:4002`, a placeholder) and a development AAGUID, has no Secure Boot and no flash encryption and is not FIDO
> certified. The OpenPGP image has additionally **never been run on a board**.

## What changed in the firmware

- **`CTAPHID_CANCEL`.** A request sent right after a cancel on the same channel could receive the cancelled job's stale result (an
  empty success, shifted replies, `CTAPHID_INIT` timeouts). Each command now has a generation, the cancel answer is sent once when
  the job really ends, and `CTAPHID_INIT` during a presence wait completes. A client that does not wait for the cancel answer can
  briefly see `CHANNEL_BUSY`.
- **FIDO UV / PIN policy.** `getAssertion` now enforces `alwaysUv`; a key whose device key is still PIN-locked refuses with
  `PUAT_REQUIRED` instead of answering with a made-up credential id and an invalid signature; turning `alwaysUv` off restores
  `makeCredUvNotRqd`. `up` defaults to true as in CTAP2. A key that already turned `alwaysUv` on and off on an older build has lost the
  `makeCredUvNotRqd` flag and does not get it back. `alwaysUv` now also applies to `up=false` probes, which could change some browser
  flows with `alwaysUv` on.
- **Dependencies** (mbedTLS, tinycbor, cJSON, mlkem/mldsa-native, libcvc) are fetched by commit SHA.

## What changed in the web installer

Deployed separately from this release. Unreadable flash type is refused; a board with the N16R8 flash size and PSRAM is labelled "same
configuration", not "hardware verified", and every board needs the acknowledgement; the partition table must match exactly for the
application-only update; interrupted-update recovery is bound to the chip, release and image.

## Status

- **Not hardware verified.** The firmware fixes are build verified (4, 8 and 16 MB) and tested with the native emulation (44 tests)
  only. The procedure for the board is `docs/hw-procedures/cancel.md`.
- **Not signed.** No signing key exists, so this release has no `firmware-manifest.json.sig` and the installer shows it as "Not
  authenticated" (`docs/RELEASE_SIGNING.md`).
- Stored data format is unchanged (`data_preserving_from` stays `0.2.0`) by code inspection only; the new remembered `makeCredUvNotRqd`
  bit is ignored by older firmware. Not tested across versions on a board.
- The published zips themselves were not flashed before the release.
