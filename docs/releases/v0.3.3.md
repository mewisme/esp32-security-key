# MultiKeys v0.3.3

This release adds **application-only firmware updates** to the web installer: a new Update firmware page (`/update`) that replaces only
the MultiKeys application on a key that already runs MultiKeys. The firmware code, the host tools and the supported boards (4, 8 and
16 MB ESP32-S3) are unchanged from v0.3.2.

> **Experimental development firmware — not suitable for protecting important accounts.** It uses a development USB
> VID:PID (`303A:4002`, a placeholder) and a development AAGUID, has no Secure Boot and no flash encryption and is not FIDO
> certified. The OpenPGP image has additionally **never been run on a board**.

## What is new

- **Update firmware (`/update`).** Writes one region, the app image at `0x20000`. The bootloader, the partition table, `nvs`,
  `phy_init` and `part0` (credentials, FIDO PIN, MKAUTH record, key name) are never written, and nothing is erased. It reads the
  running key first (read-only), compares it with the key in download mode, and refuses anything it cannot show to be compatible:
  other firmware family, other layout or flash size, downgrades, versions older than `update.data_preserving_from`. There is no
  override.
- **Not atomic.** One application slot, no rollback: an interrupted write leaves the key unable to start until the update is run
  again from download mode (the page keeps a record of the unfinished write and then offers a typed-`REPAIR` rewrite). It is not
  an OTA update.
- **Manifest:** each build now carries `update.app_only: true`. Releases up to v0.3.2 do not, so the Update page never offers
  them as a target.
- **Install wizard:** the `update-unverified` mode is gone. A key whose installed version is outside the declared compatible range
  now stops with `storage-unverified` instead of asking for an acknowledgement.
- **After the update** the page reports whether the running image SHA-256, the version, the key name and the management-PIN state
  match. FIDO credentials and the PIN are **not** read by the page; "not checked" is shown for them.

## Status

- Update page: unit and end-to-end tested against a simulated board. **Not hardware verified** at the time of tagging.
- Data preservation is by design (`part0` is not written) and by code inspection (no stored-format change since 0.2.0); it has not
  been tested across versions on a board.
- The key in download mode is not proven to be physically the key that was read before; plug in only that key.

## Which firmware file is for my board?

| Image | 16 MB | 8 MB | 4 MB | Tested |
|---|---|---|---|---|
| FIDO2 | `multikey-firmware-v0.3.3-esp32s3-16mb-fido-dev.zip` | `...-8mb-fido-dev.zip` | `...-4mb-fido-dev.zip` | 16 MB: a local build of earlier sources ran on one ESP32-S3 N16R8 (no firmware code changed since v0.3.1). 8 and 4 MB: build verified only |
| OpenPGP (Experimental) | `...-16mb-openpgp-dev.zip` | `...-8mb-openpgp-dev.zip` | `...-4mb-openpgp-dev.zip` | **Build verified only** on every size; never flashed |

The published zips themselves were not flashed before the release.
